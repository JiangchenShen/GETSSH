# GETSSH 界面设计准则 · Workbench

本文件是 GETSSH 产品界面的唯一设计规范，取代旧版「赛博霓虹／毛玻璃／Bento」规范。它定义产品体验和视觉判断，不要求现有界面已经符合，也不授权为了改视觉而移除用户已有功能。

## 1. 产品立场

GETSSH 是日常使用的 SSH 工作台，不是 SaaS 管理后台。界面首先回答四个问题：我在哪个工作区、正在连接哪台机器、是否有需要处理的风险、下一步能做什么。视觉品质来自清楚的层级、稳定的排版与准确的状态，而不是装饰数量。

- **先工作，后概览。** 终端、主机和进行中的任务是主角。首页帮助用户继续工作；Dashboard 呈现可行动的运行状态，不做四宫格 KPI 展板。
- **信息必须可信。** 只展示应用实际拥有且新鲜的数据。未采集的延迟、CPU、在线率不能靠演示数字填空；未知、检测中和异常必须可区分。
- **一个能力，一个稳定入口。** Command Center 是已有的全局搜索与调度层，不再为它另造首页、启动磁贴或第二套导航。其他中心各有明确归属，不靠在每个页面重复露出来证明存在。
- **密度为操作服务。** 主机多时能快速扫描，主机少时不留下巨大的空壳；界面在常用窗口尺寸内无需滚动才能找到主要操作。

## 2. 界面结构

| 场景 | 首要内容 | 次要内容 |
| --- | --- | --- |
| 尚未连接 | 最近使用的主机、继续上次工作、明确的新建／快速连接动作 | 工作区和真实待处理事项 |
| 已连接 | 终端与会话切换；当前主机的名称、地址和连接／信任状态 | 按需展开的文件、AI、连接详情与安全上下文 |
| 主机管理 | 可搜索、可扫描的主机列表；选中主机后就地连接或编辑 | 分组、标签、认证和网络配置 |
| 运行总览 | 活跃会话、连接异常、安全告警和可继续的操作 | 仅在能帮助决策时出现的汇总数字 |

各目的地按操作对象分工：AI 中心负责对话、历史、提示词和智能体；模型供应商、搜索及 MCP 配置归入「设置 → AI 与集成」。插件中心负责已安装插件及其操作，权限模式归入「设置 → 安全与隐私」。工作区页负责当前工作区的资产、迁移和隔离规则。应用锁、保险库、主机信任和隐私归入「设置 → 安全与隐私」；连接审计与录屏归入「设置 → 数据与日志」，不再保留独立的安全中心。安全异常可在主机或首页就地提示，并直达对应设置。常规窗口中，AI、插件和设置从底栏直达；工作区从左侧工作区导轨或资产栏标题直达。

全局导航、主机导航、会话切换和上下文工具要有不同层级。一个入口可以有快捷键和菜单访问方式，但不要在侧栏、首页、底栏同时摆同一套功能目录。状态栏报告状态；只有相关状态或异常才需要醒目的跳转。

### 首页内容约定

首页是「开始连接与继续工作」的工作台入口，不是各中心的缩略版。主页标签始终存在；切回主页不关闭终端，打开终端也不移除主页。基础模块如下；确有异常时将待处理事项提升到连接区之前：

1. **问候与定位，始终可见。** 保留按本地时间变化的问候语、日期和当前工作区名称。问候语是产品个性，不用「运行总览」之类的冷标题替代；时钟可以紧凑显示，不占据主要操作区。
2. **连接入口，始终可用。** 提供一个明确的快速连接输入，接受现有连接表单支持的地址／协议格式；旁边有「新建连接」以创建并保存配置。快速连接与保存配置是两种不同意图，不应混成一个含糊按钮。
3. **继续工作，有会话时出现。** 只给一个回到上次活跃标签的直达入口。已打开的所有终端仍由窗口标签栏负责切换；首页不再复制会话列表，也不放终端缩略图。若尚未记录上次活跃标签，就不伪称知道用户最后在做什么。
4. **最近连接，有记录时出现。** 最多列出四台最近成功连接的主机，显示别名、`user@host`、工作区／分组和真实的上次连接时间。已打开的主机动作是「切换标签」，未打开的是「连接」。当前配置只有保存顺序、没有可靠的最近连接时间；在补齐记录前只能称为「已保存主机」，不得称「最近」。完整主机管理和搜索仍在主机导航中。
5. **待处理事项，确有问题时才出现。** 只呈现应用能确认且用户能处理的连接错误、凭据保护风险或 Watchdog 异常，并给出直接去处；有异常时排在问候语之后。正常、未知、检查中分别标明；正常状态留给状态栏，不用空的安全卡片填首页。

AI 中心、插件、设置和 Command Center 保留稳定的底栏入口；当前工作区由侧栏进入，安全由设置或真实告警进入。首页不再排功能磁贴。AI 模型名称、主机总数、标签总数可用于相关位置的辅助文案，不组成固定 KPI 四宫格；未经采集的 CPU、延迟、在线率和虚构的活动流不进首页。

空状态也遵守同一结构：没有主机时突出快速连接与创建配置；有主机而无会话时显示最近连接（尚无时间记录时称「已保存主机」）；有会话时保留标签栏并提供一次继续入口。工作区切换后，首页内容和最近连接记录必须随工作区变化。窄窗口中仍应先看到问候与连接动作，次要列表可下移，不能遮挡标签栏。

## 3. 视觉语言：安静的仪器感

采用连续的工作画布、克制的工具栏和细分隔线，让内容本身形成层次。默认不在每个模块外围画一张大卡片。浮层、弹窗和临时检查器才使用明显的抬升与阴影。终端视觉优先于外框装饰。

以下为新界面的基准色，不要求一次性改掉现有主题功能。实现时应映射到语义变量，并同时提供深浅模式：

| 语义 | 深色基准 | 浅色基准 | 用途 |
| --- | --- | --- | --- |
| 画布 | `#101215` | `#F5F6F5` | 主工作区 |
| 窗口层 | `#181B1F` | `#EAEEEC` | 导航、工具栏 |
| 抬升层 | `#22262B` | `#FFFFFF` | 弹窗、检查器 |
| 分隔线 | `#343A40` | `#D9DEDC` | 区域边界 |
| 主文字 | `#E8ECEB` | `#202726` | 标题、操作与数据 |
| 次文字 | `#9DA8A7` | `#5F6D6A` | 辅助信息 |
| 操作强调 | `#8ACDBB` | `#176F60` | 焦点、选中、主操作 |

强调色一次只服务一个主焦点。成功、警告、危险使用各自的语义色，并同时配文字／图标，不能只凭颜色传意。AI、安全、插件等类别不再强制各占一种亮色。现有 DuoTone 和毛玻璃设置可继续作为用户可选主题，但不是新页面的默认骨架或强制装饰。

### 排版与组件

- 普通文字使用系统 UI 字体与可靠的中文回退；地址、用户名、端口、命令和指纹使用等宽字体。不要让全部标签都变成大写微字。
- 以标题大小、字重和留白建立层级；主机名优先于 IP，异常优先于统计。常规控件宜紧凑但保留可点击区域。
- 列表用于扫描多个主机或事件；分栏用于同时工作；卡片只用于确有独立边界的对象或状态，不作为每个内容块的默认容器。
- 圆角随层级节制使用：行与小控件约 `6–8px`，弹窗约 `12–16px`。不以 `24–32px` 大圆角统一所有页面。
- 交互反馈优先用文字、边线和背景的轻微变化；常规行与按钮不做整体缩放。过渡以约 `120–180ms` 为宜，并尊重减少动态效果设置。

## 4. 不再采用的默认套路

- 背景网格、模糊光斑、全屏渐变、到处发光的边框。
- 「欢迎语＋四张指标卡＋功能磁贴」作为首页固定模板。
- 每个功能都配一个彩色图标盒、胶囊徽标和宣传式说明文字。
- 为了显得功能丰富而复制 Command Center、主机列表或中心导航。
- 用漂亮但无法验证的遥测数据、假在线状态或安全结论填满空白。
- 为追求 Web 与桌面端 1:1 截图相同而牺牲桌面窗口行为。两端共享品牌、语义和关键控件，布局服从各自任务。

这些不是对用户可选主题的禁令；它们不再是 GETSSH 默认界面或新设计方案的起点。

## 5. 交付与验收

修改界面前先核对现有入口、真实数据来源及空／加载／错误／大量主机／已连接状态。设计稿和实现都要能回答：主要操作是否一眼可见、入口是否重复、AI／插件／工作区／设置的内容归属是否清楚、安全配置是否能从设置与告警直达、状态是否可信。

至少在常用桌面窗口尺寸检查深浅模式、键盘焦点、中文长文案、缩放与终端全屏 TUI。主要操作不得只靠悬停出现；焦点和状态需满足可读对比度。若新布局与现有主题设置冲突，优先保持功能可用，再逐步迁移视觉，而不是默默删除用户配置。
