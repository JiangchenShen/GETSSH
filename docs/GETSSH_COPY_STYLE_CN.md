# GETSSH 文案准则

> 适用范围：应用界面文字（`apps/getssh-client/src/locales/` 和组件里写死的文字）、官网 `GETSSH-WEBSITE`、发布说明
> 检查脚本：`node scripts/copy-lint.js`，只标记，不改文件
> 更新：2026-10-02

## 1. 原则：写事实，不写形容词

GETSSH 的用户每天用 SSH，很多人懂加密。看到"军工级加密"，他们会先怀疑这个产品；看到"整个数据库用 SQLCipher 加密，主密码用 Argon2id 处理"，才会相信。

- **有数字就写数字**，并且能复现：测的是什么、在什么机器上测的。
- **有机制就写机制**：用了什么算法、数据存在哪里、谁能看到。
- **安全上不做绝对承诺**。不写"绝对安全""坚不可摧"，写清楚防住了什么、还有什么没防住。
- **没做到的不写**。路线图上的功能要标"计划中"。

## 2. 三个模型怎么分工

| 步骤 | 谁来做 | 要求 |
|---|---|---|
| 第一版 | Claude 或 ChatGPT（Codex） | 把事实写全：功能、数字、限制条件。不用追求好读 |
| 第二版 | Gemini | 改成人话：短句、口语、有节奏。不加事实，不加形容词 |
| 定稿 | 负责人，加 Claude 或 ChatGPT | 跑检查脚本，删夸张词；对照第一版，确认第二版没有改错事实 |

第二版只改说法。第一版里的数字、算法名和限制条件要原样保留。Gemini 觉得哪条事实不该写，就标出来交给负责人，不要自己删。

## 3. 写第一版时（Claude、ChatGPT）

我们的毛病是"人机味"：

- **套话动词**：打造、助力、赋能、致力于、赋予。换成"做""提供""给"，或者直接写功能。
- **空洞的范围词**：一站式、全方位、全链路、闭环、无缝。列出具体包含什么、怎么衔接。
- **固定句式**：不仅……更……；无论是……还是……；不是……而是……；让……变得……。直接说结论。
- **排比三连**：更快、更稳、更安全。只留最重要的一个，并给出依据。
- **段尾口号**：每段最后一句拔高。删掉。
- **英文**：seamless、effortless、empower、unleash、robust、leverage、whether you're…、not just… but…。

| 改前 | 改后 |
|---|---|
| 我们致力于为您打造一站式 SSH 管理体验 | 主机、终端、文件传输和密钥都在同一个窗口里 |
| 不仅更安全，更带来丝滑流畅的体验 | 服务器密码存在用 SQLCipher 加密的数据库里 |
| 无论是 macOS 还是 Windows，都能无缝运行 | 支持 macOS 13 及以上、Windows 10 及以上 |

## 4. 改第二版时（Gemini）

Gemini 写得最像人话，但容易夸张：

- **量级词**：宇宙级、纳米级、量子级、史诗级、核弹级。删。
- **安全上的夸张**：军工级、军事级、银行级、坚不可摧、铜墙铁壁、绝对安全。换成算法和机制。
- **比较上的夸张**：降维打击、碾压、吊打、遥遥领先、天花板、最强。写出跟谁比、差多少；没有数字就删。
- **空洞的强调**：极致、终极、黑科技、颠覆、革命性、无与伦比、前所未有。删，或者说清楚是什么技术。
- **英文**：military-grade、unbreakable、ultimate、revolutionary、blazing fast、cutting-edge、world-class。

| 改前 | 改后 |
|---|---|
| 军工级加密，坚不可摧 | 整个数据库用 SQLCipher 加密，主密码用 Argon2id 处理，不会存下来 |
| 极致性能，毫秒级响应 | 写出实测数字和条件，例如"用原始钥匙打开一个 2000 行的加密库约 0.5 ms，不含主密码解锁（Apple Silicon Mac，getssh-store 验证）" |
| 降维打击传统 SSH 客户端 | 删掉，改成功能对比表 |

**"军工级"尤其要删。** 在安全圈，"military-grade encryption"几乎就是不靠谱产品的标志，懂行的用户看到会扣分。

## 5. 要看语境的词

下面这些词描述真实技术时可以用，但要有出处：

- **零信任**：只有每次访问都重新验证时才用。
- **毫秒级、秒级、极速、秒开**：附上测量条件，或者直接写数字。
- **企业级、生产级、工业级**：写出具体能力，例如审计日志、权限隔离。
- **零拷贝**：实现里确实没有拷贝才用。官网和应用里关于 `sftp-stream` 零拷贝的说法，要先对照代码核实。

## 6. 界面文字

- 按钮写动作，比如"连接""导出"。不写"立即体验"。
- 错误提示写清三件事：发生了什么、为什么、下一步怎么办。不写"哎呀，出错了"。
- **待定：称呼。** 应用里"您"多（`zh-CN.json`：您 40 处，你 10 处），官网新文案用"你"（`copy.ts` 里 34 处全是"你"）。由负责人定一个，定了以后写进本节。

## 7. 检查脚本

```bash
node scripts/copy-lint.js
```

默认检查应用的 `apps/getssh-client/src` 和旁边官网仓库的 `src`，跳过整行的代码注释、Markdown 代码块、测试文件和第三方许可证全文。写在代码后面的行尾注释仍会检查。

```bash
node scripts/copy-lint.js --summary
```

只看每个词出现了几次。

```bash
node scripts/copy-lint.js --strict apps/getssh-client/src/locales
```

只查指定路径；有夸张词时退出码为 1。交稿前自查用这个。

结果分三类：

- **夸张**：几乎都该删。
- **机器腔**：改成直接陈述。
- **看语境**：字面上的技术描述就保留。

脚本只标记，改不改由人决定。词表写在脚本开头，发现新的词就直接加进去。
