# 从 2.0 升级到 3.0：演练记录和步骤

10-15 整理。前半部分是 2.0 在磁盘上留下的东西、3.0 怎么处理它们，以及自动测试覆盖到哪里；后半部分是负责人用真实数据演练一次的步骤和回退办法。

## 一、2.0 留下了什么，3.0 怎么处理

2.0 和 3.0 用同一个 userData 文件夹（macOS `~/Library/Application Support/GETSSH`，Windows `%APPDATA%\GETSSH`），界面也都用 `loadFile` 加载，所以 localStorage 也是同一份。

| 2.0 的数据 | 位置 | 3.0 的处理 | 2.0 的原文件 |
|---|---|---|---|
| 服务器列表 | `profiles.json`（无主密码）、`profiles.enc`（有主密码）、`profiles.key`（2.0 保存的主密码） | 首次启动时自动导入主工作区；`profiles.key` 打不开时，界面请用户输入 2.0 的主密码 | 不改不删 |
| 插件数据 | `plugin_data/<插件名>.db` | **10-15 起**首次启动时复制到主工作区的插件目录，只做一次（`legacyV2PluginData.ts`）。之前 3.0 不读这些文件，插件升级后设置和数据都是空的 | 不改不删 |
| 已安装的插件 | `plugins/` | 原样加载，清单格式没变。后端插件改在受系统限制的独立进程里运行 | 不变 |
| 插件里的密码类设置 | 和插件数据在同一个 `.db` 里，明文 | 插件读取或设置页列出时，移进加密存储，并从文件里删掉 | 复制出来的那份被改，2.0 的原文件不动 |
| 主机指纹 | `known_hosts.json` | 同一个文件，格式相同 | 两个版本共用 |
| 连接记录 | `connection_history.json` | 同一个文件 | 两个版本共用 |
| 界面设置 | localStorage `appConfig`、`themePref` | 直接读取，缺的项用 3.0 的默认值 | 3.0 改设置后会写回 |
| 加密的设置（初始化脚本、代理） | localStorage `appConfig_secure`（2.0 用模拟钥匙串加密） | 解密后移进加密存储，localStorage 里只留一个标记 | 被标记替换 |
| 最近连接 | localStorage `getssh_recent_sessions` | 格式相同，直接用 | 两个版本共用 |

**插件安全模式**：2.0 的默认值是"普通"，所以 2.0 用户的设置里基本都是这个值。3.0 的主进程每次启动都从"安全"开始，界面把设置同步过来时，切到其他模式要先验证身份。没设主密码的用户（从 2.0 升上来时都没有）会直接通过，不会弹 Touch ID，模式和 2.0 时一样。

**再回到 2.0 会少什么**：
- 初始化脚本和代理设置：3.0 已经把 `appConfig_secure` 换成了标记，2.0 读不出来，会回到默认值；
- 在 3.0 里新加或修改的服务器、插件数据：2.0 看不到。

服务器列表和插件数据的原文件 3.0 都没动，2.0 打开后还是原来的样子。

## 二、自动测试覆盖到哪里

| 内容 | 测试 |
|---|---|
| 2.0 和 1.x 的各种服务器文件格式、保存的主密码、默认端口、重复和空白的行、只导入一次 | `legacyV2Profiles.test.ts`；端到端 `v2-*` 的 9 个阶段，用真实的存储模块 |
| 插件数据复制：只复制到主工作区、3.0 已有数据时不覆盖、跳过链接和不像插件库的文件、带上 WAL 日志、只做一次 | `legacyV2PluginData.test.ts`（用真实的 getssh-kv 写 2.0 的文件）；端到端 `v2-setup` / `v2-import` |
| 2.0 用模拟钥匙串加密的 `profiles.key` 和设置 | `legacyV2Profiles.test.ts`、`secretStore` 的测试 |
| 加密格式 | 按 2.0 的 `getssh-vault` 源码（`v2.0.0-R7K4S`）逐字节核对过：`GETSSH_V2` + 32 字节盐 + 12 字节 IV + 16 字节标签 + 密文，PBKDF2-SHA256 十万次，AES-256-GCM |

没有覆盖的：
- 打包版在真实电脑上的首次启动界面。自动测试走的是同一套主进程代码，但不开窗口。
- 用真实 2.0 设置（localStorage）升级：你的 localStorage 已经被 3.0 开发版改过，下面的演练也用不上它。设置的读取有单元测试，默认端口的处理有端到端测试。
- Windows 真机：等笔记本准备好以后一起测。

## 三、负责人用真实数据演练

你的 userData 文件夹 10-03 起一直被 3.0 开发版使用，已经不是纯粹的 2.0 状态了。其中服务器列表和插件数据 3.0 没动过，还是 2.0 留下的样子，可以拿来演练。

为了不碰你现在每天用的数据，演练在一个新的 macOS 用户里做。

### 准备

1. 在"系统设置 → 用户与群组"里新建一个**普通**用户，比如 `getssh-rehearsal`。
2. 在你自己的账号里，把下面这些复制到 `/Users/Shared/getssh-v2/`（只复制，不移动）：
   - `~/Library/Application Support/GETSSH/` 里的 `profiles.json`、`profiles.enc`、`profiles.key`（有哪个复制哪个）；
   - 同一个文件夹里的 `plugin_data/`、`plugins/`、`known_hosts.json`。
   - **不要**复制 `~/.getssh`，那是 3.0 的数据；新用户要像刚从 2.0 升上来一样，没有它。
3. 准备 3.0 的安装包，放到 `/Users/Shared/`：用发布流程打的 DMG（10-20 起，手动运行发布流程也会把安装包留在那次运行的 Artifacts 里）。要用 10-15 以后打的包，之前的包还不会导入插件数据。

### 演练

1. 登录新用户，把 `/Users/Shared/getssh-v2/` 里的东西复制到 `~/Library/Application Support/GETSSH/`（文件夹不存在就新建）。
2. 打开 3.0。应用没有 Apple 开发者签名，第一次打开时 macOS 会提示无法验证开发者：macOS 13、14 上在应用上点右键选"打开"；macOS 15 及以上打开"系统设置 → 隐私与安全性"，在下方点"仍要打开"。然后逐项检查：
   - 服务器都在主工作区里，别名、端口、用户名、私钥路径对得上；
   - 有密码的服务器能直接连上；
   - 2.0 设过主密码、而 `profiles.key` 打不开时，界面会请你输入 2.0 的主密码，输入后能导入；
   - 插件都在，插件自己的设置还在；
   - 连之前连过的服务器时，不会提示"新主机"或"主机指纹变了"。
3. 关掉 3.0 再打开，服务器不会重复出现。
4. 有问题就截图，或者记下哪台服务器、哪一步，发给 Claude。

### 回退

演练只发生在新用户里。结束后在"系统设置 → 用户与群组"里删除这个用户，选"删除个人文件夹"，再删掉 `/Users/Shared/getssh-v2/`。你自己账号的数据和钥匙串从头到尾都没被碰过。

正式升级时如果出了问题：
- 2.0 的服务器文件和插件数据都还在原处，重新装回 2.0 就能看到。
- 3.0 的数据在 `~/.getssh`。把它整个移走（不要直接删），3.0 下次启动会当作新装，重新从 2.0 导入。在 3.0 里新加的服务器和改过的设置都在移走的那份里，不会出现在新的这份里。
